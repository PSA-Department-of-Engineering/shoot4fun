**FINDINGS**

1. **MAJOR** — Permanent schema divergence between fresh and migrated databases: on a virgin DB the CREATE mints `expires_at TIMESTAMPTZ NOT NULL` with **no default** (backend/shoot4fun_backend/adapters/outbound/postgres/postgres_account_repository.py:54) and the `ADD COLUMN IF NOT EXISTS ... DEFAULT now()` no-ops (:59-60), so the default exists only on tables that lived through the migration — any future INSERT omitting `expires_at` errors on fresh installs while silently writing instantly-expired sessions on migrated ones, and the new test enshrines exactly this divergent shape (`column_default is not None`, backend/tests/integration/test_account_pg_upgrade.py:124-125). Inserts always supply the value today (:203-205), so nothing breaks now, but the one-statement fix (`ADD COLUMN` then `ALTER COLUMN ... DROP DEFAULT`, or asserting only nullability/type) would have converged both shapes.

2. **MAJOR** — The upgrade test is destructive against whatever `TEST_DATABASE_URL` names: `DROP TABLE IF EXISTS account_sessions` (test_account_pg_upgrade.py:50) discards every session in the target database, breaking the repo's own documented shared-DB hygiene precedent ("Rows are cleaned by user_id prefix, per the #51/#63 precedent… targets the accounts this module created and nothing else", backend/tests/integration/test_account_pg_roundtrip.py:12-16); the module docstring's claim that "Cleanup removes only the rows this module minted" (test_account_pg_upgrade.py:17-18) is false on the setup side.

3. **MINOR** — The "carried legacy session no longer resolves" leg is mostly vacuous: the container's sweep loop runs immediately on startup with no initial sleep (backend/shoot4fun_backend/container.py:154, :161-163), so the backfilled row (expires_at = ALTER-time `now()`, postgres_account_repository.py:60) is usually already deleted when the 401 is asserted (test_account_pg_upgrade.py:130) — an unknown token returns 401 too, so the run typically proves "row gone", not "resolution honours expiry"; pass/fail is stable either way, which makes it a silent attestation weakness rather than a flake.

4. **MINOR** — Private-symbol coupling plus setup-residue window: rebuilding the table via the adapter's private `_SCHEMA` (test_account_pg_upgrade.py:42, :49) means any unrelated statement later added to `_SCHEMA` fails this fixture's setup with a confusing error, and if `_reshape_to_pre_expiry` raises after the sentinel-account insert but before the fixture yields (:62-73), the purge at :94 is unreachable and rows remain.

5. **MINOR** — Minted users are recorded only after the status assert (test_account_pg_upgrade.py:133-135 appends post-assertion), so a failing mint leaks an unpurged guest account plus a live TTL session onto the shared database (a live session shields its guest from sweeps per postgres_account_repository.py:236-241).

6. **NOTE** — No `@pytest_intent.intent(...)` marker: sibling pg tests attest claims formally (test_account_pg_roundtrip.py:77, :95) while this regression cites INT-019 only informally in prose (test_account_pg_upgrade.py:1), leaving it invisible to the intent ledger; harmless to CI's orphan-marker audit, but the delivery-fix delta ships unattested.

7. **NOTE** — Execution-order and multi-statement hazards checked clean: the ALTER sits immediately after its CREATE and before the index build (postgres_account_repository.py:50-61), depends on nothing not yet true on either a virgin or a pre-expiry database, and asyncpg executes the parameterless multi-statement string atomically under simple query protocol; `now()` is STABLE so the PG≥11 backfill is metadata-only (brief ACCESS EXCLUSIVE lock retaken idempotently on every connect(), :101-106).

8. **NOTE** — Contract conformance clean: only `account_sessions` DDL changes; ADR-0007's envelope guarantees (docs/adr/0007-arsenal-forward-compatible-envelope.md:28-45) and ADR-0008's "no migration / no second auth path" clauses (docs/adr/0008-shop-surface.md:17-18, :41-43) govern the Arsenal JSONB shape and the session choke point, neither touched — resolution predicate (:214-216) and sweep predicate (:234) are byte-identical to before, so INT-037/INT-038 are unaffected.

9. **NOTE** — Environment surfaces check out: skip-if-unset gating matches CI's postgres service (.github/workflows/test.yml:37-51), local Windows runs without Postgres skip cleanly, the e2e job runs in-memory (no DATABASE_URL), and the DDL adds no injection surface (static string, all caller SQL parameterized).
