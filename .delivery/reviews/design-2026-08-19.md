# Adversarial Design Review — `shoot4fun` (DESIGN-kind, follow-on)

I reviewed the Protopane prototype (`slug="shoot4fun"`, 3 screens: `account`, `profile`, `arsenal`) against the locked visual identity (`docs/brand.md`, `docs/logo.svg`).

## BLOCKERS
None.

## NON-BLOCKING observations

1. **`arsenal` screen — `border-transparent` on the Loadout badge** (`arsenal` html, line ~11: `rounded-full border border-transparent bg-primary`). `border-transparent` is a built-in Tailwind utility, not a brand color, so it passes token discipline — but it silently disables the `--border` token on that chip. Minor visual inconsistency with the other bordered chips; not a defect against the standard, just worth a build note.

2. **All three screens use `bg-gradient-to-r from-primary to-accent`** (the 1px top accent bar). This is derived purely from brand tokens (`--primary` → `--accent`), so no new hue is introduced and token discipline holds. It is, however, a presentational treatment not explicitly codified in `brand.md` (the brand doc defines 19 key tokens and 3D-scene bindings, but no gradient spec). The build will need to either adopt this flourish or drop it to stay "same brand" — flag for the build handoff to confirm intent, no gate impact.

## Verifications that PASSED
- **Token discipline:** Every color in all 3 screens resolves through a token (`bg-primary`, `text-muted-foreground`, `border-border`, `bg-secondary`, `hover:bg-accent`, `bg-primary/90`, etc.). No literal hex, `rgb(...)`, or numeric `hsl()` anywhere. `border-transparent` is a utility, not a brand color.
- **Identity reuse:** The saved Protopane theme tokens **exactly equal** `docs/brand.md`'s 19-key set — all keys (`--background` … `--font-sans`) match byte-for-byte, including `--radius 0.5rem` and `--font-sans Inter, system-ui, sans-serif`.
- **Logo:** `docs/logo.svg` exists and is a real, non-empty SVG (600×160 wordmark + crosshair lockup, brand-derived colors). Acceptable as the supplied rung-1 logo.
- **Dimensions covered:**
  - `account` → LOGIN-001/002: opt-in login shown (guest state, "Keep this name" + "Sign in", recovery-code panel). ✓
  - `profile` → PROF-001/002/003: server-synced state, "restored on every device", and "Local changes reconciled… automatically" all written/shown. ✓
  - `arsenal` → ARS-001/002/003/004: functional tile, player-model placeholder (3D scene — acceptable as placeholder), gracefully-empty inventory, and forward-compatible shape note all shown/written. No other build-relevant dimension is missing. ✓
- **No invented look:** No new hues, fonts, or palettes introduced; everything reads from the delivered 19-key identity.

VERDICT: PASS
