#### Non-blocking (surface to the operator)

1. **`onboard_app` icon is unpinned** — `handoff.md:59`. The §3 call shape is `onboard_app(name="shoot4fun", …, image_components=["server", "client"], expose_mcp=False)`; the `…` elides `display_name`, `description`, and `icon` (all three are required by the MCP `onboard_app` tool). `display_name` is trivially derivable from §1 and `description` from the proposal's verbatim ask, but the `mdi-*` icon name is not pinned anywhere in the handoff. The build will have to default or invent (the brand's crosshair suggests `mdi-crosshairs`/`mdi-target`/`mdi-crosshairs-gps`, but the convention is not recorded).
2. **INT-015 §9 row description omits the horn/sting e2e** — `handoff.md:136` vs `intent_claims.spec.ts:108`. The §9 row says "Web Audio analyser sees gunshot, hit, footstep envelopes; volumes from `localStorage`" — but the plan-time `spec.ts` carries a third INT-015 marker at line 108 (`lobby_horn_and_results_sting_fire_on_match_state_transitions`) added under NB13. The marker is in place; the §9 prose was not updated to describe it. The build will find the marker, but the table understates the test surface.
3. **`e2e/foundry/deployment.spec.ts` is the odd-one-out for INT-012** — `handoff.md:133` vs `handoff.md:256`. §2 says the two test trees are `backend/tests/` and `apps/client/e2e/`; §17 step 3 mirrors that ("port into `backend/tests/`; port into `apps/client/e2e/`"). But §9's INT-012 row targets `e2e/foundry/deployment.spec.ts` at the repo root — a third tree, neither under `backend/` nor `apps/client/`. The build can resolve by following §9, but the prose under §2/§17 under-specifies a third location.
4. **"keyed by the PSA-database role" is ambiguous in §7** — `handoff.md:95`. "The leaderboard stores the highest per-arena score keyed by the PSA-database role, not by player identity" reads as if data is keyed by the database role (which would put all rows in one bucket), not as "stored under the role's ownership." INT-017's statement ("only the highest per-arena score is retained") is clearer. The build will likely read INT-017 to disambiguate, but the handoff could be tightened.
5. **`interaction: manual` still persists in the body** — `handoff.md:153, 241`. NB12 removed the `interaction:` frontmatter field, which the prior review treated as the fix. But §10's table reads `Interaction: \`manual\`` and §17's kickoff reads `\`interaction: manual\``. Per `REF-Delivery.md` §1, interaction "is passed per invocation and never persisted in the scratch" — the body is the scratch. A build that reads these as flags would mis-set its mode; a build that treats them as documentation is fine. The prior fix was incomplete; the body mentions should be removed (or relabelled "the launcher's interaction at this run, not a persisted flag") so a future build-runner doesn't read them as authoritative.
6. **LDR-002 leaderboard UI design deferral is not pinned in §4** — `design.md:309-312`. Design §2.3 records the persistent best-score leaderboard as "**not yet designed**" and "deferred to a P2 design pass." The handoff's §4 says the visual identity is locked and lists the durable homes, but does not surface this deferral or pin a resolution. The build will find the note in `design.md` and follow it, but the handoff could pin the per-match-results treatment (1st place brand-coloured, reachable from a lobby or results tab) as the P2 build-time default, so the P2 design gap is explicit at the plan gate, not hidden in `design.md`.
