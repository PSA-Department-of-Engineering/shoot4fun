# Adversarial Review — Shoot4Fun Shop Surface (kind=design)

Fresh-context pass over the candidate design identity before the design-gate close
(REF-Delivery §1). Reviewer had no hand in producing the artifact and saw no prior
review of it. Evidence read: `protopane-psa_get_project("shoot4fun")` (theme tokens +
all 13 screens' html/css), `docs/brand.md`, `.delivery/proposal.md`,
`.delivery/request.md`, and disk glob confirming `docs/logo.svg` and
`docs/logo-monogram.svg` both exist.

## History

Two prior fresh-eyes passes returned VERDICT: FAIL; their blockers were fixed in the
prototype before this pass:

- Pass 1 blockers: (a) rarity→colour semantics shown by example only with an open tier
  set — fixed by adding a five-tier rarity legend (`data-rarity-legend`) to
  `shop-catalog`; (b) catalog→detail interaction path unpinned with two competing
  unlock entry points — fixed by making catalog cards whole-card links
  (`data-item-link`) to the detail page, moving Unlock to detail only.
- Pass 2 blockers: (a) Legendary badge used white text over the primary→accent
  gradient, contradicting brand.md's documented dark-on-gold AA decision — fixed to
  `text-accent-foreground`; (b) small `text-primary` links/active filter pill below AA
  — fixed to high-contrast treatments (`text-foreground` underlined link,
  `bg-secondary text-foreground border-primary` active pill). The main-menu Shop tile
  "Coming soon" contradiction was also resolved (tile enabled).

## What holds

- **Token discipline**: scanned all 13 screens' html and css for literal hex, `rgb()`,
  or numeric `hsl()` — zero hits; every screen composes token-backed utilities only
  (`from-primary to-accent`, `bg-secondary`, `decoration-border`, etc.), and all `css`
  fields are empty.
- **Theme vs brand.md**: all 19 canonical keys match the brand.md table byte-for-byte,
  including `--primary` `12 95% 55%`, `--accent` `50 100% 50%`, `--accent-foreground`
  `15 10% 12%` (the documented dark-on-gold AA decision), `--radius` `0.5rem`, and
  `--font-sans`. No second look minted.
- **Logo**: both SVGs confirmed on disk; the prototype consistently uses the text
  wordmark treatment, matching the existing ten screens.
- **Requirement coverage**: browse (`shop-catalog` with filters + rarity legend),
  detail (SHOP-002's name/description/preview/rarity all present), acquire (Unlock flow
  citing ADR-0007 envelope write), apply (`shop-acquired` Applied state) — all three
  verbatim deliverables from request.md shown live; currency exclusion stated
  on-screen, matching proposal scope notes.

## Non-blocking observations

1. **Rarity semantics collide with `--primary`'s established meaning**
   (`shop-catalog`, rarity legend + card badges). The prototype maps "Rare" to
   `bg-primary` (brand Hot Sauce orange) — but everywhere else in the shipped look
   orange means *interactive/active* (lobby "Selected" map row, Ready dots, profile
   "Synced", primary buttons). A builder reading the catalog will inherit a system
   where the brand colour is simultaneously "this item's rarity tier" and "this thing
   is selected/live." It is shown live (legend pins it deliberately), so the contract's
   letter is met, but the semantic overload is undocumented in any written artifact and
   will read as a bug to players familiar with the rest of the UI.
2. **White-on-orange fails AA for the new small-text badges** (`shop-catalog` card
   badges, `shop-item-detail` header badge): `text-primary-foreground` (#FFFFFF) on
   `--primary` #F94B1F is ≈3.6:1, below the 4.5:1 small-text threshold — and these are
   `text-xs` badges, smaller than the buttons that already carry the pair. The token
   pair is part of the locked identity (brand.md ships `--primary-foreground: 0 0%
   100%`), so fixing it here would mint a second look; flagging so the build knows the
   "Rare"/"Epic"-adjacent badges sit below AA while the dark-on-gold decision
   (documented) does not.
3. **Legendary badge extends the dark-on-gold decision without documenting it**
   (`shop-catalog` legend): dark `--accent-foreground` text over the
   `from-primary to-accent` gradient measures ≈4.7:1 at the orange end — passes AA,
   but marginally, and brand.md records the accessibility rationale only for gold. One
   sentence in brand.md would pin it.
4. **SHOP heading visually impersonates the Wordmark role** (`shop-catalog` h1:
   `font-black tracking-tight text-primary`, matching the enumerated Wordmark surfaces
   SHOOT4FUN/MATCH OVER). brand.md enumerates exactly four Wordmark surfaces and SHOP
   is not one, so the written rule resolves it to body typography — but the prototype's
   identical styling invites a builder to reach for Russo One. A size/family note for
   large section headings would remove the ambiguity.
5. **Item imagery is placeholder-only** (dashed "Skin preview" boxes), consistent with
   the existing Arsenal placeholder convention — acceptable for a prototype, but the
   build will have to invent the real preview treatment (aspect ratio, art source)
   since CAT-001's catalog authorship isn't visualized.

## Verdict basis

The §3 contract's structural legs hold: dimensions shown or written, token discipline
clean, committed logo, single inherited brand language, requirement spine covered live.
No blockers remain.

VERDICT: PASS
