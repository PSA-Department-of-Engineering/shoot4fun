### NON-BLOCKING observations (ranked most-severe first)

1. **Self-contradiction on where/how the new e2e specs run** (`handoff.md:106,108` vs `handoff.md:137`). §6 step 3/5 place the markers in `apps/client/e2e/account.spec.ts` and `apps/client/e2e/arsenal.spec.ts` (root `e2e/`, the same level as `match.spec.ts`), but §9 item 6 says those same specs "run against the public URL (the `foundry/**` Playwright project, gated on `SHOOT4FUN_HOST`)". Root specs are not under `foundry/**`; the shipped pattern is that root specs run against a locally started server (`startedMatch` in `match.spec.ts:609`) while only `foundry/handshake.spec.ts:50` / `foundry/deployment.spec.ts:16` run against the public host. Failure it causes: the build will either place specs at root (making §9 item 6's "against the public URL" evidence claim false) or mis-file them under `foundry/` (contradicting §6). Reconcile the two before the build writes the evidence chain so §9 item 6 is truthful.

2. **AccountPanel mount integration point is not pinned** (`handoff.md:106`, `intent.yaml:382-392`). The handoff says "mount `AccountPanel` into the menu/launch surface" but `MainMenu.tsx:20-86` has no panel slot for it (only `versus`), and the only `AccountPanel` reference in the codebase is its own definition (`apps/client/src/ui/views/organisms/AccountPanel.tsx:25` — confirmed orphaned, zero imports). The exact integration (a new `MainMenu` panel state like `versus`, or a header affordance) is a real decision the build must make. It is tolerable only because `handoff.md:163-167` explicitly authorizes the smallest-reasonable-choice fallback; note it as a plan defect in `build.md` as that section already anticipates.

3. **ARS-004 envelope shape is undecided** (`handoff.md:73,109`, `intent.yaml:464-474`). INT-029's contract test proves "an over-shaped payload round-trips without loss," but the envelope (versioned field set, unknown-field preservation) is left for ADR-0007, which the build authors. This is intentional and pointed-to (not a silent gap), so it is not a blocker — but the claim is not yet attestable until that shape exists, and the plan should make explicit that ADR-0007 + the module must precede the INT-029 marker activation (it does, at §6 step 6, but the dependency order is worth a one-line emphasis).

4. **`robot.glb` attribution pointer is slightly off** (`handoff.md:65` vs `apps/client/src/scene/CharacterLibrary.ts:14` and `apps/client/public/models/README.md`). The asset is present and CC0 1.0 (confirmed `public/models/robot.glb` + `public/models/README.md`), but the handoff tells the build to "confirm its license/attribution in `docs/`" whereas the provenance README actually sits beside the model in `public/models/`, not `docs/`.
